# 实验报告八阶段工作流

## 核心原则

1. **讲义驱动**——实验讲义的明确要求是最高准则
2. **全局返工**——发现问题时回到源头阶段重新执行
3. **不确定时提问**——遇到任何模糊内容时必须停下来向用户提问，严禁自行推测
4. **预防胜于检查**——写的时候就对，不要指望审校来兜底

## 全局返工机制

**核心规则**：任何阶段发现问题时，不是在本阶段修修补补，而是**回到源头阶段重新执行，并再次流经后续所有阶段**。

| 发现问题 | 回到阶段 | 说明 |
|---------|---------|------|
| 报告内容遗漏讲义要求 | 阶段1 | 重新读讲义，更新《实验要求清单》 |
| 原始数据有问题 | 阶段2 | 检查数据源、格式、记录 |
| 手写数据识别存疑 | 阶段2 | 向用户确认后再继续 |
| 数据处理结果异常 | 阶段3 | 重新选择/调整处理方法 |
| 图表质量问题 | 阶段4 | 改布局、改配色、重新输出 |
| 素材版权问题 | 阶段5 | 换来源、补标注 |
| 排版/格式问题 | 阶段6 | 改 LaTeX 源码 |
| 数据不一致 | 阶段2 或 3 | 核对原始数据源 |
| 数值管线断裂 | 阶段3 + 阶段6 | 重新统一数值来源 |

**返工后必须重新编译、重新校对。**

## 阶段1：需求理解（核心）

**目标**：在碰任何数据之前，从实验讲义中提取全部要求，形成《实验要求清单》。这份清单是后续所有阶段的验收标准。

### 提取内容

| 类别 | 提取要点 |
|------|---------|
| 实验目的 | 有几条？报告正文中需要逐条回应 |
| 实验原理 | 核心公式、需要推导什么、需要哪些原理图 |
| 实验装置 | 仪器列表、型号（**严禁自行推测**）、参数 |
| 实验步骤 | 关键步骤、校准流程、操作注意事项 |
| 数据处理 | 分bin方式、拟合模型、误差处理、数据筛选 |
| 思考题 | 有几道？在正文还是附录回答？ |
| 报告格式 | 章节结构、页数、原始数据附录、误差分析 |

### 区分硬性要求 vs 建议性描述

| 类型 | 示例 | 处理方式 |
|------|------|---------|
| 硬性要求 | "分20个区间" "进行指数拟合" | 必须严格执行 |
| 建议性描述 | "可用Origin处理" | 可选择其他等效工具 |
| 未提及 | 讲义完全没说的处理方法 | 自行选择最佳方法，记录理由 |

### 输出《实验要求清单》

```
《实验要求清单》
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[硬性要求]
□ 数据处理：分 bin 范围 ___, 间隔 ___, 共 ___ 个区间
□ 拟合模型：__________
□ 需要对比的标准值：__________
□ 思考题 ___ 道，需回答在附录

[建议性描述]
□ 推荐使用 Origin 处理（可用 Python 替代）

[讲义未提及，需自行决定]
□ 是否加权拟合？理由：__________
□ 是否含本底项？理由：__________
```

## 阶段2：数据审阅

**在《实验要求清单》指导下进行。**

### 2.1 读取原始数据

1. 读取原始数据文件，确认编码格式
2. 统计总行数、列数，识别列的含义和单位
3. 检查缺失值、空行、异常格式行
4. 计算基本统计量：最小值、最大值、均值、标准差
5. 绘制原始数据初稿，目视检查异常值
6. **与讲义要求比对**：数据范围、采样方式是否一致？

### 2.2 手写数据识别（高风险环节）

若原始数据为手写记录（照片/扫描件），**这是最高风险环节之一**。

**必须执行**：
1. 至少用两种独立方法获取识别结果（OCR + 人工逐字录入 / 不同 OCR 引擎）
2. 交叉比对，标记不一致处
3. 对易混淆字符重点复核：**0↔6、1↔7、3↔8、小数点位置、正负号**
4. 物理合理性校验：与讲义预期数量级对比

**易混淆字符清单**：0↔6（极高风险）、1↔7（极高风险）、3↔8（中高）、小数点位置（极高风险）

详见 `practical-guide.md` 第 1.4 节。

### 提问触发点 2.1 — 数据格式无法识别

**必须向用户提问。** 模板：
```

[显示前5行]

请确认：
A. 第X列是[物理量1]，第Y列是[物理量2]
B. 数据格式是[格式描述]
C. 需要跳过前N行表头
D. 其他（请说明）
```

### 提问触发点 2.2 — 发现异常值

**必须向用户提问。** 模板：
```
在数据审阅中发现以下异常：

[具体描述]

请确认如何处理：
A. 剔除该数据点（视为坏点）
B. 保留但标注为异常
C. 检查原始实验记录是否有误
D. 其他（请说明）

推荐：A（负时间无物理意义）
```

### 提问触发点 2.3 — 手写数据识别存疑

**以下情况必须停止处理，向用户提问确认：**
- 两种识别方法的结果不一致
- 字符模糊，人工复核仍无法确定
- 识别结果的数量级与物理预期严重不符
- 同一列数据中出现突兀异常值（可能是小数点位置错误）

**提问模板**：
```
手写数据识别中发现存疑之处，请您核对原始记录后确认：

[附上识别结果对比表，高亮存疑行]

存疑1：第X行，第一个数字识别为 [A/B]，原始手写是 [0/6/8]？
存疑2：第Y行，数值为 [1.23/12.3]，小数点位置是否正确？
存疑3：第Z行，符号为 [正/负]，原始记录是否有负号？

请直接回复确认后的正确数值，或提供该页更清晰的照片。
```

**严禁在存疑未解决的情况下继续数据处理。**

### 提问触发点 2.4 — 数据量与讲义不符

**必须向用户提问。** 模板：
```
数据量检查发现问题：
- 讲义要求：[描述]
- 实际数据：[描述]

请确认：
A. 数据缺失，需要补充测量
B. 部分数据保存在其他文件中
C. 实际实验时未按要求完成全部测量
D. 其他（请说明）
```

## 阶段3：数据处理

**核心原则**：讲义有明确要求的，严格按讲义做；讲义没说的，自行选择最佳方法并**记录理由**。

### 3.1 按讲义要求处理

- 如果讲义明确了分 bin 方式、拟合模型、数据范围，严格执行
- 如果讲义推荐使用特定软件（如 Origin），可用 Python 等效替代

### 3.2 数值管线初始化

**这是预防数据不一致的根本方法。**

```python
# 脚本输出 LaTeX 宏定义
with open('results/params.tex', 'w') as f:
    f.write(f"\\newcommand{{\\valJs}}{{{Js:.4f}}}\n")
    f.write(f"\\newcommand{{\\valJr}}{{{Jr:.4f}}}\n")
    f.write(f"\\newcommand{{\\valHc}}{{{Hc:.0f}}}\n")
```

LaTeX 中引用：
```latex
\input{results/params.tex}
Fe 的 $J_s = \valJs$ emu，$H_c = \valHc$ Oe。
```

**铁律**：正文中每个数值必须来自脚本输出的唯一来源，严禁手动输入。

## 阶段6：报告撰写

**核心原则：写的时候就对，不要指望审校来兜底。**

### 6.1 数值管线（铁律）

- 所有数值通过 `\input{results/params.tex}` 或 `\newcommand` 自动填充
- **严禁手动输入任何数值**
- 唯一例外：讲义给定的标准值、仪器参数等固定值

### 6.2 分步写作 + 即时自检

不要一次性写完所有内容再检查。每写完一个模块，立即执行自检：

| 写作动作 | 立即执行的检查 |
|---------|--------------|
| 每插入一张图 | 来源检查 + 渲染检查（强制转 PNG 查看）+ 引用检查 |
| 每写完一个数据段落 | 每个数值能否追溯到脚本输出？四舍五入是否一致？ |
| 每写完一个原理段落 | 符号是否与讲义一致？公式编号是否正确？ |
| 每写完结论 | 每个数值是否在前面出现过？有无过度推断？ |

详见 `checklist.md` 第一节"写作阶段即时自检"。

### 6.3 报告结构填充

1. 修改封面信息（标题、姓名、学号、院系、日期）
2. 按讲义要求填充各章节
3. 插入图表，使用交叉引用 `Figure~\ref{}` / `Table~\ref{}`
4. 多组数据明确区分（自主测量 vs 参考/累计数据）
5. 思考题按讲义要求的位置回答

## 阶段7：校对迭代

**七维排查是粗筛，逐页逐图逐句检查是精筛。必须全部执行，不能跳过。**

### 7.1 七维排查（快速扫描）

1. **数据一致性**：图中参数框 ↔ 正文公式 ↔ 结果汇总表，三处数值完全一致
2. **讲义符合性**：对照《实验要求清单》，逐项检查
3. **措辞规范**：科学用语准确、客观、不口语化
4. **排版质量**：编译无 error、无 overfull hbox
5. **图表质量**：清晰度、无重叠、caption 完整
6. **逐页检查**：从封面到参考文献，逐页浏览 PDF
7. **参考文献**：格式统一、引用完整

详见 `checklist.md` 第二节"七维排查清单"。

### 7.2 逐页检查（对每一页执行）

检查页码连续性、章节编号正确性、内容完整性、排版细节。

详见 `checklist.md` 第三节"逐页检查"。

### 7.3 逐图检查（对每一个图执行）

**必须直接查看图片文件**（转 PNG 用 ReadMediaFile），不能仅看 PDF 缩略图。

检查：来源合法性、渲染质量（无乱码/重叠/截断）、与正文一致性、物理正确性。

详见 `checklist.md` 第三节"逐图检查"。

### 7.4 逐句检查（对关键段落执行）

对**摘要、结论、数据处理结果、标准值对比、思考题答案**逐句审查。

**高危表述**："这说明...""与理论值一致""误差很小""如图X所示""根据文献[3]"

详见 `checklist.md` 第三节"逐句检查"。

## 阶段7.5：独立教师批改

**在七维排查和逐页逐图逐句检查之后，启动独立评审 Agent。**

### 为什么需要独立 Agent 评审

- 写作 Agent 容易产生"确认偏误"，对自己写的内容不够苛刻
- 独立评审 Agent 不带上下文包袱，能发现数据不一致、逻辑漏洞
- 模拟真实教学场景，提前暴露会被教师扣分的问题

### 评审 Agent 的输入（严格控制上下文）

评审 Agent **只能看到**：
1. 最终报告全文（LaTeX 源文件或 PDF 提取文本）
2. 实验讲义核心要求（《实验要求清单》中的硬性要求）
3. 数据处理结果（关键数值、图表文件列表）
4. **每个图片文件**（要求逐一查看）

**严禁**将写作过程中的草稿、废弃方案泄露给评审 Agent。

### 评审 Agent 必须执行的操作

1. 逐页浏览 PDF
2. 每个图单独查看（逐一检查渲染质量）
3. 逐句精读摘要和结论
4. 随机抽查数值，交叉验证一致性
5. 审查"说明""反映""证明"等强论断是否有数据支撑

### 评审 Agent 输出格式

```
### 1. 总体评价（100字以内）

### 2. 问题清单（按严重程度分类）
```
